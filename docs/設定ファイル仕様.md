# 印刷屋プラグイン 設定ファイル仕様（Ver.6）

印刷屋プラグイン（rex0220 Print craft）の設定 JSON の形式の正本です。AI はこの文書に従って JSON を組み立て、`pcraft-authoring normalize` で派生値を生成・検査してから `settings/` に保存します。
正本は print-craft の `src/config/schema.ts`（`CONFIG_SCHEMA`）で、キーの一覧は `docs/schema-manifest.json` に機械生成されています。この文書のキー表と manifest は `tools/test/spec-sync.test.mjs` が照合します（キーの追加・削除があるとテストが落ちる）。

## 0. まず読むべき 5 点

1. **封筒形式で書く**。最上位に `date` / `pluginName` / `pluginID` / `PluginVersion` / `appId` / `appName` と、設定本体のキーを同じ階層に置く（dashboard の `config` 入れ子とは違う）。`pluginID` は `"rex0220 Print craft plugin"`、`PluginVersion` は印刷屋の版（`npx @rex0220/print-craft-authoring-tools version` の「印刷屋プラグイン: 版 N」。例 `"6"`、`"7"`）。
2. **AI が書くのは「AI」の列のキーだけ**。「tools」の列（`formula`、`usedFields`、`id`、`views`、`pluginUOG`、更新項目の `type` / `ptcode` など）は `normalize` が fields と計算式エンジンから生成する。書いても信用されず上書きされる。
3. **項目はフィールドコードで書く**（ラベルではない）。`fields/<app>.json`（`pcraft-authoring fields`）で確かめる。無い項目は `normalize` がエラーにする。
4. **帳票は HTML テンプレート + `${式}` + テーブルは `TABLE_HTML`** で書く（レシピ集）。文字列の差し込みは `${ESC_HTML(項目)}`。`${式}` を属性値の中に置かない。
5. **保存先の添付ファイル項目（`filecode`）、用紙、向き、dpi、「ボタンを押したとき」（`printMode`）を明示する**。空のままにしない。

## 5. 派生値（tools が生成する。AI は書かない）

| 派生値 | 元 |
| --- | --- |
| 行の **formula** | `formulaSet` から `//` コメントを除いたもの |
| 行の **usedFields** | 実エンジン（印刷屋と同じ計算式ライブラリ）で検証用レコードを評価したときに参照した項目と回数 |
| 更新項目の **calcInfo.usedFields** | 有効な更新項目の行の `usedFields` の和 |
| ルートの **usedFields** | 全ボタンの `calcInfo.usedFields` の和 + テーブルの子を使っていればその親 |
| ルートの **pluginUOG** | 有効なボタンの更新項目に UINFO / OINFO / GINFO を使う式、またはユーザー / 組織 / グループ選択の項目があれば `true` |
| 各行の **id** | 行番号（1 から） |
| ボタンの **views** | `viewsCsv` を `{ id: 1 }` に |
| 更新項目の `row_type` / `type` / `lookup` / `ptcode` / `fieldlabel` / `required` | fields と layout |

`normalize --check` は、入力にこれらが入っていたとき生成した値と比べて差を出す（エクスポートした設定を戻すときの確認）。

| `pluginInfos[].tagsInfo.printMode` | `preview` `confirm` `direct` |

`4R` / `5R` / `8R` は印刷屋が受け付けるが設定画面の候補には無い（`normalize` が警告）。`externalRefs` の既定: 新しい設定は `block`、キーが無い既存の設定は印刷屋が `allow` として動かす（1 章）。

## 7. 制約

- 文字列の上限は 1 値 200,000 文字（`html` / `css`）、計算式は 20,000 文字（`formulaSet` / `formula`）。設定画面の読み込みとインポートの検証もこの上限（`CONFIG_LIMITS.maxStringLength` = 200,000）。
- kintone のプラグイン設定は全体で 256 KB（圧縮後）。`normalize` が同じ符号化で測り、超過はエラー。画像は BASE64 で埋め込まず、添付ファイル項目 + `#{&f(…)}` か、小さな SVG にする。
- 配列の上限: `pluginInfos` 100、`cssInfo` 500、`guestsInfo` 5,000、HTML 設定と更新項目の行 1,000。
- 真偽値は `true` / `false` で書く（旧版の `"Y"` などは読めるが書かない）。

## 8. 検査すること / しないこと

`normalize` が検査する: 封筒（`pluginID` / `PluginVersion`、`appId` は正の整数）、入力の大きさ（4 MB）、スキーマ（型・上限。**未知のキーは黙って落とす**。派生値はスキーマで検証した値から作る）、列挙、`filecode` の実在と型、HTML 設定の 1 行目 `$out` / 2 行目 `$fname` の有無、有効なボタン名の重複、更新項目の可否、計算式の構文（実エンジン）、使う項目の実在、HTML（許可した要素・属性だけ。URL の形は Chrome と同じ前処理で判定、属性値の `${式}`、iframe は `.env` の接続先と同じオリジンだけ。`.env` に接続先が無ければ iframe は使えない）、CSS（コメントと文字列を区別し、エスケープを復号してから `@import` / `expression(` と `url()` などの URL）、帳票の行の計算式（**警告だけ**: HTML を作る関数の使用、`TAG` の要素名や `ATTR` / `STYLE` / `BATTR` の値が定数でない、文字列の定数の HTML / CSS は HTML / CSS と同じ検査を警告として。文字列の中の `//` はエラー）、外部参照（`externalRefs`。`allow` とキーが無い設定は利用者の承認 `allowExternalRefs` が無ければエラー、不正な値はエラー。`block` の設定の HTML / CSS の外部 URL はエラー = 印刷屋が除くので帳票に出ない）、外部 URL の承認（`allow` の設定の HTML / CSS と Web フォント。`policy/authoring-policy.json` の `allowExternal`。形も検証する）、保存値の大きさ（kit と同じ符号化。キーと値のバイト数）。

**検査しない（事故はここで起きる）**: 帳票の見た目、計算式の**実行結果**（`TABLE_HTML` の中身、レコードの値、関数が組む HTML。静的に追わない。`preview` で見る）、添付ファイルの画像の有無、権限のコードとゲストのメールの実在、一覧 ID の実在、Web フォントが読めるか。**インポート後に印刷屋がレコードの値を HTML として入れる経路（`${式}`、`TABLE_HTML` のセル、`FVAL`）による文章や表の崩れは防げない**（kintone 以外への読み込みとスクリプトは、印刷屋 Ver.6 が `externalRefs` = `block` の設定で描画の前に除く。`allow` では除かない。アプリ管理者とレコードを編集できる人の範囲で担保する）。

## 10. 反映方法

1. `pcraft-authoring normalize settings/<ファイル>.json --fields fields/<app>.json` でエラー 0 にする（警告は人が読む）
2. `pcraft-authoring preview … --record records/<app>-<id>.json` で `out/<ボタン名>.html` を Chrome で開いて見た目を確かめる
3. 既存設定の変更なら `pcraft-authoring diff <前> <後>` で差分を人が見る
4. kintone のアプリの設定 → プラグイン → 印刷屋プラグインの設定 → **設定をアップロード** → ファイルを選ぶ → **取り込み方**を選ぶ → **保存する** → アプリの設定を**運用環境に反映**
5. 詳細画面でボタンを押して PDF を確かめる（保存先があれば添付ファイル項目に入る）

取り込み方（印刷屋 Ver.6）: **全置換** = 設定全体をファイルの内容にする / **一部置換** = ファイルのボタンごとに、置き換える今のボタンを選ぶ（選ばないボタンは取り込まない）/ **追加** = 選んだボタンを末尾に足す（同じ名前があれば「名前 (2)」）。一部置換と追加では、ファイルに `cssInfo` があれば共通 CSS を丸ごと置き換えるかをチェックで選び（既定は置き換えない）、他の共通の設定（`externalRefs`、`fontInfo`、`menuInfo`、`pluginComment`、`pluginDescription`、`guestsInfo`）はアプリの今の設定のまま。派生値はファイルの値のままなので、取り込んだボタンは保存のときに印刷屋が検査し、このアプリに無い項目、派生値の無い計算式（`normalize` を通していない）、添付ファイル項目でない保存先、更新できない更新項目があれば保存しない。

ファイルの検証に失敗した場合、既存の設定は変わらない。

## 11. 既定値のファイル

- `docs/defaults/cssInfo.json` … 共通 CSS の既定の 4 行（`table` / `card` / `comm` / `invoice`）
- `docs/defaults/menuInfo.json` … メニュー表示の既定
- `docs/defaults/calcInfo.json` … 更新項目を使わないときの `calcInfo`
