# バージョンアップ手順

このテンプレートから作った自分のリポジトリ（設定を作るフォルダー）を、新しい印刷屋プラグインや新しい tools に合わせる手順です。**フォルダーを作り直す必要はありません。** 自分の設定（`settings/` など）と `.env` はそのまま使えます。

> **tools 1.2.0 に上げる前に（`environments.json` を使っている場合だけ）:** `environments.json` の各環境に `role`（`development` か `production`）を書きます（`environments.example.json` が見本。`environments.json` は自分で直します。AI は書けません）。1.2.0 から、`role` の無い環境のフォルダー（`kintone/<ホスト名>/…`）は tools が何も変えなくなり（`take`、`edit`、`normalize` の書き戻し、`fields`、`record`、`preview` が止まる）、本番（`production`）のフォルダーは新しいダウンロード / pull を足すことだけになります。構成 2（同じドメインで開発用と本番のアプリ）では、`apps` に無いアプリのフォルダーも変えられなくなるので、`apps` に足します。`environments.json` を使っていない（`settings/` だけの）場合は何も変わりません

## 1. 何を更新するか

| 更新するもの | 場所 | いつ |
| :--- | :--- | :--- |
| 印刷屋プラグインの zip | `.env` の `PCRAFT_PLUGIN_ZIP` | アプリの印刷屋プラグインを新しい版にしたとき（2 章） |
| tools（`@rex0220/print-craft-authoring-tools`） | `package.json`、`node_modules/` | tools が新しい zip に対応していないと出たとき、新しい tools の直しや機能を使いたいとき（3 章） |
| テンプレートの文書と設定（`CLAUDE.md`、`docs/`、`.claude/settings.json` など） | テンプレートのファイル | tools と一緒に（3 章） |

今の版は、ターミナルで次のコマンドで確かめます。

```
npx @rex0220/print-craft-authoring-tools version
```

1 行目に tools の版と tools が扱う印刷屋の版（tools 1.1.0 以降は「扱う印刷屋 Ver.6 以降、API 1, 2」）、2 行目に `.env` の zip の印刷屋の版が出ます。公開されている tools の最新の版は `npm view @rex0220/print-craft-authoring-tools version` で分かります。

## 2. 印刷屋プラグインを新しい版にしたとき

1. アプリに入れたものと同じ版の zip（配布元から入手したもの）を手元に置きます
2. `.env` の `PCRAFT_PLUGIN_ZIP` を、その zip の場所に書き換えます（`.env` は自分で直します。AI は `.env` を読み書きできません）
3. 確かめます（`7` はアプリに入れた印刷屋の版）:
   ```
   npx @rex0220/print-craft-authoring-tools version --expect 7
   ```
   最後に `--expect 7: 一致` と出れば終わりです

- tools 1.1.0 以降は、印刷屋の版を上げても、tools の対応する authoring API の版のままなら tools を上げずに使えます（tools は zip のプラグイン ID で印刷屋の zip かを確かめます）
- 前の版の印刷屋で作った `settings/` の設定は、そのまま `normalize` / `preview` に使えます。`normalize` は情報 `envelope.version.upgrade` を出し、書き出す設定の `PluginVersion` を zip の版にします
- 「印刷屋プラグインの版 … には対応していない」「authoring API の版 … には対応していない」と出たら、3 章で tools を上げます（tools 1.0.0 以前は印刷屋 Ver.7 以降の zip を読めません）

## 3. tools とテンプレートを上げる

### 3.1 テンプレートのファイルだけを置き換える（おすすめ）

始める前に:

- 作業中の設定をコミットしておきます（`git status` で確かめる）
- テンプレートのファイル（`CLAUDE.md`、`README.md`、`.claude/settings.json` など）を自分で直していた場合、その変更は消えます。Claude Code の許可を足すなら `.claude/settings.local.json`、git で無視するファイルを足すなら `.git/info/exclude` に書いておきます

VSCode のターミナル（PowerShell でもコマンドプロンプトでも同じ）で:

```
git remote add template https://github.com/rex0220/print-craft-authoring.git
git fetch template
git checkout template/main -- .claude .mcp.json .env.example .gitignore CLAUDE.md README.md LICENSE environments.example.json package.json package-lock.json docs tools settings/README.md requirements/example.md policy/README.md
npm ci
npx @rex0220/print-craft-authoring-tools version
git commit -m "テンプレートの更新を取り込む"
git push
```

- `git remote add` は初回だけです（2 回目からは「already exists」と出るので飛ばします）
- `git checkout` で置き換わるのは、テンプレートのファイルだけです。自分の `settings/` `requirements/` `fields/` `kintone/` `policy/authoring-policy.json` と `.env` `environments.json` `env/` `records/` `out/` は変わりません
- `git checkout` が置き換えたファイルはコミットの対象に入っているので、`git add` は要りません
- 置き換えるファイルの一覧は、テンプレートの版で変わることがあります。最新の一覧は GitHub の README の「テンプレートの更新を取り込む」にあります。一覧のファイルがテンプレートに無いと `pathspec … did not match` と出て何も置き換わらないので、そのファイルを外して実行し直します
- テンプレートで消えたファイルは手元に残ります。気になれば消してください
- `environments.json` を使っていれば、各環境に `role` を書きます（この文書の先頭の注意）
- 最後に Claude Code のセッションを始め直します（新しい `CLAUDE.md` と許可の設定を読むため）
- `git merge template/main` では取り込まないでください。テンプレートから作ったリポジトリはテンプレートと履歴がつながっていないので、手を入れていないファイルまで衝突し、解き方によっては `policy/authoring-policy.json` の承認が消えます

### 3.2 Claude Code に頼む

3.1 のコマンドは Claude Code にも実行させられます。

```
docs/バージョンアップ手順.md の 3.1 のとおりに、テンプレートの更新を取り込んで
```

- git と npm のコマンドのたびに確認が出るので、内容を見て許可します
- この文書が手元に無いとき（古いテンプレートから作ったとき）は、「README の『テンプレートの更新を取り込む』のとおりに」と頼みます
- `.env` の zip の入れ替え（2 章）は自分で行います

### 3.3 tools だけを急いで上げる

文書はそのままで、tools だけを上げます（`1.3.0` は上げたい版。1.1.x 以前から上げるときは先頭の注意も）。

```
npm install --save-exact @rex0220/print-craft-authoring-tools@1.3.0
npx @rex0220/print-craft-authoring-tools version
```

`package.json` と `package-lock.json` が変わるのでコミットします。文書（`CLAUDE.md` など）は古いままなので、後で 3.1 を行ってください（3.1 で `package.json` もテンプレートのものに置き換わります）。

### 3.4 フォルダーを作り直す（git の操作に慣れていないとき）

1. README の「セットアップ」の 1〜2 のとおりに、テンプレートから新しいリポジトリを作り（private）、`npm ci` します
2. 古いフォルダーから、次のものを新しいフォルダーへ写します
   - `settings/`（`README.md` 以外）、`requirements/`（`example.md` 以外）、`fields/`
   - `policy/authoring-policy.json`
   - `.env`（zip の場所を新しい版にするなら、2 章のとおり書き換える）
   - 使っていれば `environments.json`、`env/`、`kintone/`、`.claude/settings.local.json`
   - `records/` と `out/` は写さなくてかまいません（取り直す・作り直すことができます）
3. `npx @rex0220/print-craft-authoring-tools version` で確かめ、新しいフォルダーで Claude Code を開きます（Windows で README の「確認を出さないようにするには」を行っていたら、新しいフォルダーでも行います）

これまでの設定の変更の履歴（git）は、古いリポジトリに残ります。

## 4. つまずいたら

| 出たもの | すること |
| :--- | :--- |
| `印刷屋プラグインの版 7（…）には対応していない。tools が対応する版: 6` | tools 1.0.0 以前です。3 章で tools を 1.1.0 以降にします |
| `authoring API の版 … には対応していない` | tools を新しい版にします（3 章） |
| `印刷屋プラグインの zip ではない（プラグイン ID …）` | `.env` の `PCRAFT_PLUGIN_ZIP` が印刷屋の zip か（別のプラグインの zip でないか）確かめます |
| `PluginVersion N の設定を、それより古い印刷屋の zip …` | 新しい版の印刷屋で作った（ダウンロードした）設定を、古い zip で検査しています。`.env` の zip をアプリに入れた版にします |
| `.env` に `PCRAFT_ALLOW_UNKNOWN_PLUGIN=1` がある | tools 1.1.0 で廃止しました。消してかまいません |
| 手元の文書が `npx pcraft-authoring` と書いている | tools 0.1.1 から、コマンドは `npx @rex0220/print-craft-authoring-tools` です。3.1 で文書を新しくします |
