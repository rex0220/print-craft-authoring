## 2. 使い方の流れ

1. **はじめに**: 状態を確かめる（作業フォルダー、印刷屋の zip、kintone の接続）。足りないものは利用者が設定する
2. **新しい帳票**: アプリの番号 → 項目を取る → プレビューに使う代表のレコード → 帳票を書いて保存（検査を通る）→ プレビュー → 反映（設定画面でアップロード。印刷屋の設定が無いアプリは全置換、ボタンを足すなら追加）
3. **形を先に試す**（アプリがまだ無い、式の動きを確かめたい）: お試しアプリ（架空の値）で 1 ボタンや式を試す。お試しアプリの項目は利用者のアプリのものではないので、作るときは利用者のアプリの項目で書き直す
4. **今の帳票を変える**: 4 章
5. **最後は印刷屋で**: 利用者が詳細画面（一覧帳票は一覧画面）でボタンを押し、PDF を確かめる。プレビューは近似（画像はダミー、Web フォントは読まない）

## 3. 頼み方（新しい帳票）

伝えるとよいこと（分からなければ AI が聞く）:

- アプリの番号（かアプリの URL）。どの環境（開発・本番）のアプリか
- 帳票の種類、用紙と向き（A4 縦など）
- 載せる項目と並び（ラベルでよい。AI がフィールドコードに当てて確かめる）。表にするテーブルと列、合計・税
- ボタンの名前、ボタンを出す条件（例: PDF がまだ無いとき）、ファイル名
- PDF の保存先（添付ファイルの項目か、ダウンロード）、押したときに確認するか
- 作った後に更新する項目（例: 発行済みのチェック）
- デザインの好み（例: 共通 CSS の見積書をもとに、見出しを濃い色に）。見本の画像があれば添える

例:

```
印刷屋で見積書の帳票を作りたい。アプリは 3740。A4 縦で、宛名（御中）、見積番号、発行日、明細の表と小計・消費税・合計。PDF は添付ファイル項目「見積ファイル」に保存。
```

```
アプリ 381（案件管理）の一覧画面に、表示中のレコードを表にした「案件一覧」ボタン（A4 横）を作って。顧客名・部署名・案件名・確度・プラン費用・オプション費用・合計費用。費用の合計欄も。
```

```
見積書の帳票（宛名、見積番号、見積日、明細の表、合計）を作りたい。kintone のアプリはまだ無いので、まず形を試して見せて。
```

```
請求書の帳票で、発行日を和暦（令和8年10月20日 のように）で、支払期限を発行日の翌月末日で表示したい。
```

```
帳票の関数について QA を 10 題作って
```

```
エスケープと文字列の差し込みに関して QA を 10 題作って。答えは最後にまとめて
```

## 4. 今の帳票を変える

流れ:

1. **今の設定を作業フォルダーに置く**: kintone の API ラボ（プラグインの設定情報を取得する API）を有効にした環境なら AI が取る（pull）。取れなければ、利用者が印刷屋の設定画面の「設定をダウンロード」で保存した JSON を作業フォルダーの `inbox/`（接続のファイルがあるとき）か `settings/` に置く
2. **AI が写しを直す**: ダウンロード・pull したファイルは書き換えず、写し（`-edit.json`）を直す。頼まれていない所（ボタンを出す画面、一覧帳票か詳細画面か、出す一覧）は変えない
3. **差分を見る**: 変える前と後の差を利用者が確かめる
4. **プレビュー**: 直したボタンを代表のレコードで
5. **反映**: 設定画面でアップロードし、取り込み方は **一部置換**（直したボタンを選ぶ）。ボタンを足しただけなら **追加**

例（記事や確かめで実際に使ったもの）:

```
印刷屋の見積書の発行元を「株式会社〇〇」に変えて、明細の表に型番の列を足して
```

```
備考欄を追加して
```

```
社印が文字に重ならないように、中央に移動して
```

```
金額の数字をもう少し太くして
```

```
見積書をベースに注文書を作成して
```

```
96 dpi 版を追加して
```

```
請求書の発行日を和暦に、お支払期限を発行日の翌月末日にして
```

伝えるとよいこと: どの帳票か（ボタンの名前、設定のファイル）、変えたい所と変えた後の形、確かめに使うレコード。変えたくない所があれば添える。

## 5. AI がしないこと・利用者がすること

- AI は kintone に書き込まない。設定の反映（アップロード → 保存 → 運用環境に反映）と、レコードの追加・変更は利用者
- 一覧 ID、権限のユーザー・組織・グループのコード、ほかのアプリの画像の fileKey は推測しないので、聞かれたら利用者が伝える
- kintone の接続のファイルとトークンは利用者が設定する（AI は読まない・書かない）
- PDF の見た目（1 ページに収まるか、書体、はみ出し）は、印刷屋のプレビューと PDF で利用者が確かめる
