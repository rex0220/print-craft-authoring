# sample: 盤面図（KIF 形式の将棋の棋譜 → A4 縦の局面の図。指定した手数・全局面・範囲）

kintone に書いた将棋の棋譜（KIF 形式の移動元付きの指し手）を 1 手ずつ進めて、盤面図の PDF を作る帳票。棋譜の読み取り・盤を進める計算・誤りの検出・盤の SVG まで、計算式だけで組む。実機で確認済み（2026-10-16。印刷屋 **Ver.8**、駒の枠あり 7 本・枠なし 10 本）。tools 2.1.0 以降で検査・プレビューできる。Qiita の記事「AI に将棋の棋譜から「盤面図」を作らせる」の帳票。

| ファイル | 内容 |
| --- | --- |
| `settings.json` | `normalize` を通した形（派生値あり）。そのままインポートできる（アプリ番号 4327 は読み替える）。駒を字だけで描く枠なし版。ボタンは「盤面図（指定した手数）」「盤面図（全局面）」「盤面図（範囲）」の 3 つ（93 KB） |
| `settings-frame.json` | 駒を五角形の枠と字で描く枠あり版（最初に作った見た目。96 KB）。`settings.json` と違うのは HTML 欄の定数の SVG の部品と設定の説明文だけ。ボタンの名前が同じなので、アップロードすると入れ替わる |
| `fields.json` | `pcraft-authoring fields --app 4327` の出力（対局名・対局日・手合・先手・後手・棋譜・メモ・表示手数・開始手数・終了手数・盤面図PDF。接続先は `https://example.cybozu.com` に置き換えてある） |
| `record.json` | プレビュー用の見本のレコード（例会 第 2 局〈角換わり・121 手〉。表示手数 50、範囲 41〜56。棋譜は AI が手元の将棋のプログラムで指した自作の対局で、先手・後手の名前は架空。`record --fields-from` の出力と同じ形） |

```
npx @rex0220/print-craft-authoring-tools normalize docs/samples/盤面図/settings.json --fields docs/samples/盤面図/fields.json --dry-run
npx @rex0220/print-craft-authoring-tools preview docs/samples/盤面図/settings.json --fields docs/samples/盤面図/fields.json --record docs/samples/盤面図/record.json --out-dir out
```

枠あり版は、`settings.json` を `settings-frame.json` に替える。

要点:

- 1 つのボタンは帳票の行 1 つ。HTML 欄は、式が `JSON_P($html, 0)` で読む定数の JSON（正規表現・表・SVG の部品。約 14,000 字）で、式が全ページを組む。式は 1 ボタン約 3,400〜4,200 字（上限 2 万字）
- 盤は 81 マス × 3 字の文字列（筋段の数字 2 字 + 駒 1 字。並びは 1 段目の 9 筋から）。駒は英字 1 字で、先手は大文字・後手は小文字、成駒は「次の字」（歩 `P` → と `Q`、角 `B` → 馬 `C`）、空きは `.`。持ち駒は `|▲飛角金銀桂香歩|△飛角金銀桂香歩` の駒の字の後ろに数（漢数字）。棋譜は、まとめて `REPLACERE` 9 回で 1 手 1 つの字句（`#5▲2288BC２二角成`）にする。「同」は前の字句の移動先を後ろ読みでさかのぼって入れる
- 1 手は `REPLACERE` 2 回。状態 `@直前の手 #手 #手 … §盤|▲持ち駒|△持ち駒§§表` の 1 つの文字列に、「引く」（`g` なし。移動元・移動先に今ある駒、取った駒の持ち駒の字と新しい数を、先頭の手に書き足す）と「書き換える」（`g`。選択肢 9 つの正規表現 1 つで、移動元・移動先・持ち駒・先頭の手を変える。正しい手でなければ先頭の手に `!` を付けて残りの手を消す）をかける
- 1 手ずつ進めるのは `ARRAY_FOR` のループ。ループの前の `LET` で状態 `u` と局面の履歴 `h` を決め、ループの中で `FSET(変数, 値)` で書き換える（`LET` の変数は項目と同じ表に入るので `FSET` で書き換えられ、次の回でも読める。ループの中の `LET` で外と同じ名前に代入すると、外の変数が消えるので使えない）。回す数は手の字句（`#`）の数（200 まで）:
  `u, t, lp, ARRAY_FOR(MIN(200, LENGTH(REPLACERE(mv, "[^#]", "g", ""))), k, ARRAY(FSET(u, REPLACERE(u, qa, ra)), FSET(u, REPLACERE(u, qb, "g", rb)), FSET(h, h & "¶" & u))), t, u,`
- `FSET` は `ARRAY(…)` の中に並べる（`ARRAY` の中は 1 回ずつ前から順に評価される。`CONCAT` の中に置くと 2 回評価される）。数の 0 を `FSET` で入れると空になる（`"0"` なら 0）
- 最初の版は、ループを使わず、1 つの `LET` の中で同じ変数に代入し直す形（`u, REPLACERE(u, qa, ra), u, REPLACERE(u, qb, "g", rb), g, g & "¶" & u`）を 200 手ぶん並べ、50 手（`REPLACERE` 100 個）ずつ `DIC_ITEM(DIC("p", LET(…)), "p")` で包んでいた（式は 1 ボタン約 1.6 万字。出力は今の形と同じ）。エンジンは 1 つの名前につき左から 100 個まで呼び出しを取り出しておき、101 個目からは字のまま残すので、包まないと変数が読めず `getVal FIELD CODE NOT FOUND` になる（五線譜のサンプルの要点と同じしくみ）
- 図は、局面ごとに関数を呼ばず、局面の履歴（最大 201 局面）をまとめて `REPLACERE` 10 回で HTML と SVG にする。駒の位置は、筋段の数字の後ろに 0 を付けて座標にする（置き換えの文字列 `translate(-$010 $020)`。`$01` は 1 つ目の組）。図を 8 つずつページに包むのは `((?:[^¤]*¤){1,8})` の 1 回。盤の SVG には width・height（20 倍の 1960 × 1940）を付けて img で縮める（付けないと html2canvas で崩れる）
- 評価回数は手の数に比例し、見本の 5 局で 1 ボタン約 970〜2,710 回（121 手で全局面 2,625 回。上限 10 万回の 2.7% まで）。式の出した局面は、4 局（30・121・78・64 手）で Python で進めた局面と 1 局面ずつ比べて全部一致
- 誤り（移動元に自分の駒が無い・移動先に自分の駒・持ち駒に無い駒を打つ・打つ先に駒・相手の玉を取る・読めない手・1 手目が同）は、そこで止めて 1 ページ目の上の赤い枠に何手目かと理由を出す。図は止まる前の局面まで。数値の項目が空かは `ISBLANK` で見る（`= ""` は 0 でも真）
- 範囲: KIF 形式の移動元付きの指し手（「７六歩(77)」「同　歩(23)」「５五角打」「２二角成(88)」）、平手、200 手まで（超えたら注記を出し、第 200 手まで）。移動元の無い書き方（▲７六歩、右・左・直・上・引・寄）は読めない手として止める。平手以外の手合、局面からの開始（詰将棋など）、変化（分岐）、駒の動き方と反則（二歩・王手放置など）は扱わない。駒の字の書体は SVG の中で Hiragino Mincho ProN・Yu Mincho・MS Mincho の順（Windows の PC では未確認）
