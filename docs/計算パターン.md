# 計算パターン（帳票の計算式。やりたいこと → やり方）

帳票の `${式}`、3 行目の計算式、ボタン表示条件（`$out`）、ファイル名（`$fname`）に書く式の書き方。目的の言葉（和暦、曜日、支払期限、年度、ゼロ埋め、改行、空、端数、郵便番号、置換をまとめる、ループ、大きい帳票 …）でこの文書を検索する。帳票の組み立て（HTML テンプレート、`TABLE_HTML`、ページ）は [帳票レシピ集.md](帳票レシピ集.md)、関数の引数は [関数一覧.md](関数一覧.md)。
元は計算式プラグインの計算パターン集（`rex0220/formula-authoring` の `docs/計算パターン.md`、`19632d7`）のうち帳票でも使う節（空・比較・端数、日付・時刻、値・文字列）で、印刷屋と計算式プラグインの計算式エンジンは同じもの（印刷屋 Ver.9 は計算式プラグイン Ver.102 のエンジン）。✔ の例は、tools に同梱のお試しアプリ（`formula-sample`）と架空の値で印刷屋 Ver.9 の計算式エンジンに評価させて確かめたもの（結果は [計算パターン_検証.md](計算パターン_検証.md)。`${…}` に差し込まれる文字。エンジンの版が変わるたびに作り直す）。記事は `https://qiita.com/rex0220/items/<番号>`（計算式プラグインの記事。利用者に案内するとき）。

ここに無い値や端の動きを断言するときは、お試しアプリ（print-craft MCP の `pcraft_try`、CLI の `try`）で確かめる。

## 帳票に差し込むとき

- `${式}` は結果を文字にして差し込む。空は `""`、真偽は `true` / `false`、配列は `,` 区切り ✔。`${…}` の中には改行と `}` を書けない（印刷屋は `${` から最初の `}` までを 1 つの式として読む。長い式は 3 行目の計算式に書いて目印に差し込む）
- 文字列の項目は `${ESC_HTML(項目)}`（`<` `>` `&` をエスケープ）。複数行は `${REPLACEALL(ESC_HTML(項目), NEWLINE(), "<br>")}`（`REPLACE` は最初の改行だけを置き換える。`"\n"` は改行にならない。改行は `NEWLINE()`）✔
- 金額は `${YEN(項目)}`（`\` 付きの桁区切り。印刷屋が帳票の `\` を `&yen;` に置き換えるので `¥1,234` に見える。空は空。2 つ目の引数で小数の桁数）✔。項目の型の書式（桁区切り・単位）で出すなら `${FVAL(項目)}`（帳票関数リファレンス）
- **日付の項目をそのまま `${日付}` に書くと数（epoch 秒。例 1768402800）になる**。`${DATE_FORMAT(日付, "YYYY年M月D日")}` か `${FVAL(日付)}`（2026-01-15）で書く。日時の項目そのままは `2026-01-15 09:30`、時刻は `09:30`。`DATE_ADD` などの日付の関数の結果は `2026-02-15` の形 ✔
- **日時は PDF を作る PC（ボタンを押した人のブラウザー）のタイムゾーン**で表示される（`DATE_FORMAT` の 3 つ目の引数で固定できる）✔

## 空・比較・端数の決まり（どの式にも効く）

| 決まり | 例（結果） | 注意 |
| --- | --- | --- |
| 空の数値を計算すると空のまま | `数値1 + 1`（空 → 空、0 → 1、2.5 → 3.5） | 0 にしたいなら `NVL(数値1, 0) + 1` ✔ |
| 空との比較は偽。空の判定は `= ""` / `ISBLANK` | `数値1 > 0`（空 → false）、`ISBLANK(数値1)`（空 → true）、`ISBLANK(数値1, 数値2)`（全部空で true） | `IF(項目, …)` は **0 も偽**。**数値の 0 も `= ""` で真**になるので、空だけを見分けるなら `ISBLANK`（0 → false）✔ |
| ゼロ除算は空（エラーにならない） | `数値1 / 数値2`（数値2 が 0 → 空） | 帳票では空の欄になる ✔ |
| 比較は、両方が数に見えれば数として、そうでなければ文字順 | `"2" > "10"` は false（数として）、`"2" > "10a"` は true（文字順） | 数でない文字に `* 1` を掛けると空 ✔ |
| 端数: `ROUND` は 0 から遠い方へ（2.5 → 3、-2.5 → -3）、`ROUNDDOWN` は 0 へ（-2.5 → -2）、`ROUNDUP` は 0 から遠い方へ（-2.5 → -3）、`INT` は小さい方へ（-2.5 → -3）、`MOD` の符号は割られる数（`MOD(-7, 3)` → -1） | `ROUND(1.005, 2)` → 1.01、`0.1 + 0.2` → 0.3（10 進で計算）、消費税の切り捨て `ROUNDDOWN(小計 * 0.1)` | 割り切れない値は 20 桁（`1 / 3 * 3` → 0.99999999999999999999）。割った後は `ROUND(…, 桁)` ✔ |

## 日付・時刻

| やりたいこと | やり方 | 式の例 | 確かめること・注意 | 記事 |
| --- | --- | --- | --- | --- |
| 日付の書式 | `DATE_FORMAT(日付, "書式")` | `DATE_FORMAT(見積日, "YYYY年M月D日")`、`DATE_FORMAT(日付, "YYYY/MM/DD")` | 書式は関数一覧の DATE_FORMAT。空の日付は空 | ✔ |
| 曜日 | `DATE_FORMAT` の `"ddd"`（英語）/ `"d"`（0 = 日曜〜6）で日本語に | `IF(日付, DATE_FORMAT(日付, "YYYY年M月D日") & "（" & ARRAY_GET(ARRAY("日","月","火","水","木","金","土"), DATE_FORMAT(日付, "d") * 1) & "）", "")` → 2026年10月18日（日）、休日の判定 `IN(DATE_FORMAT(日付, "d") * 1, 0, 6)` | 曜日の名前は英語（Sun）。空の日付は `"d"` が 0 になるので `IF` で分ける | ✔ |
| 和暦（元号と年、月日） | `LET` + `IFS` + `DATE_DIFF` | 下の「和暦の式」（2026-10-18 → 令和8年10月18日、2019-04-30 → 平成31年4月30日、2019-05-01 → 令和元年5月1日） | `DATE_FORMAT` に和暦の書式は無い。元号の開始日以上で判定し、年は開始年の 1 月 1 日との差 + 1。「元年」は年が 1 のときを分ける | 9f8eb7607fec4f22060a ✔ |
| 年度（4 月始まり） | `FISCAL_YEAR` | `FISCAL_YEAR(日付, "04-01")`（2026-03-31 → 2025、空 → 空） | 始まりの月日を変えられる | c2d593d5c7e685f21f7c ✔ |
| 支払期限（翌月末日）・翌月初・N 日後 | `DATE_ADD` + `DATE_ENDOF` / `DATE_STARTOF` を `DATE_FORMAT` で | 翌月末日 `DATE_FORMAT(DATE_ENDOF(DATE_ADD(請求日, 1, "month"), "month"), "YYYY年M月D日")`（1/31 → 2月28日、12/15 → 翌年 1月31日、うるう年 2月29日、空 → 空）、翌月初 `DATE_STARTOF(DATE_ADD(日付, 1, "month"), "month")`、30 日後 `DATE_ADD(日付, 30, "days")` | 1 か月足してから月末を取る（1/31 + 1 か月 = 2/28）。帳票に出すときは `DATE_FORMAT` で書式を決める | 924409c1fc59ade5dc72 ✔ |
| 日数の差 | `DATE_DIFF(前, 後, "days")` | `IF(AND(開始日, 終了日), DATE_DIFF(開始日, 終了日, "days"), "")` | （前, 後）の順で、逆にすると負の数。**空の日付は 1970-01-01 として数える**（-21166 のような値。両方空なら 0）ので空を分ける | 2e0fa7c8c83512acba3c ✔ |
| 時刻項目の差（勤務時間など） | `DURATION_AS` で分にして引く。日をまたぐなら `MOD(… + 1440, 1440)` | `MOD(DURATION_AS(退勤, "minutes") - DURATION_AS(出勤, "minutes") + 1440, 1440)`（09:30〜18:15 → 525、22:00〜06:00 → 480）。表示は `DURATION_FORMAT(DURATION(分, "minutes"), "%H時間 @m分")` → 8時間 45分 | **`DATE_DIFF` に時刻項目を渡すと NaN**（日付が無い）。空の時刻は 0 分になるので `IF` で分ける | ✔ |
| 日時の表示 | `DATE_FORMAT(日時, "YYYY-MM-DD HH:mm"[, タイムゾーン])` | `DATE_FORMAT(日時, "YYYY-MM-DD HH:mm")`（09:30Z が Asia/Tokyo で 18:30）、日本時間に固定 `DATE_FORMAT(日時, "YYYY年M月D日 H時m分", "Asia/Tokyo")` → 2026年10月18日 18時30分 | PDF を作る PC のタイムゾーンで変わる。海外からも使うなら 3 つ目で固定する | ✔ |

### 和暦の式

```
LET(
  fDate, DATE_FORMAT(日付),
  eDate, IFS(fDate >= "2019-05-01", "2019-01-01", fDate >= "1989-01-08", "1989-01-01", fDate >= "1926-12-25", "1926-01-01", fDate >= "1912-07-30", "1912-01-01", fDate >= "1868-01-25", "1868-01-01", ""),
  gengo, IFS(fDate >= "2019-05-01", "令和", fDate >= "1989-01-08", "平成", fDate >= "1926-12-25", "昭和", fDate >= "1912-07-30", "大正", fDate >= "1868-01-25", "明治", ""),
  y, DATE_DIFF(eDate, fDate, "years") + 1,
  IF(eDate, gengo & IF(y = 1, "元", y) & "年" & DATE_FORMAT(日付, "M月D日"), "")
)
```

- 年だけなら最後の行を `IF(eDate, gengo & y & "年", "")`（2019-05-01 → 令和1年）
- 帳票の 3 行目の計算式で使うなら、結果を `LET` の変数にして `REPLACE($html, "##wareki##", …)` で目印に差し込む（帳票レシピ集の 0 章）。HTML の `${…}` に書くなら 1 行にする

## 値・文字列

| やりたいこと | やり方 | 式の例 | 確かめること・注意 | 記事 |
| --- | --- | --- | --- | --- |
| 条件で値を変える | `IF` / `IFS` / `SWITCH` / `IN` | `IF(分類 = "明細", 数量, "")`、`SWITCH(区分, "A", 1, "B", 2, 0)`、`IN(分類, "A", "B")`、`IFS(条件1, 値1, 条件2, 値2, 既定)` | 該当なしのときの値。`IN` は true / false | ✔ |
| 空のときの既定 | `NVL` | `NVL(LASTIF(…), 0)` | `SUMIF` / `SUM` は該当なしで 0、`LASTIF` は空 | ✔ |
| 選択した値・名前を文字列にする（ユーザー・組織・グループ、チェックボックス・複数選択） | 項目をそのまま、または `SEL_NAME` / `JOIN` | `担当者`（名前を「, 」区切りで）、`SEL_NAME(担当者, "text", "、")`、改行で並べるなら `SEL_NAME(担当者, "text", "<br>")`、`チェック1`（値を「,」区切りで）、`JOIN(チェック1, "、")` | ユーザー・組織・グループは名前を「, 」（カンマと空白）で、チェックボックス・複数選択は値を「,」で区切る。作業者は `SEL_NAME(作業者, "text")`。コードが要るなら `SEL_CODE(…, "text")`。名前に `<` などが入りうるなら `ESC_HTML` で包む | ✔ |
| テーブルの文字列を 1 つにまとめる | `JOIN` + `TARRAYIF`（空の行を除く）/ `CONCAT` | `JOIN(TARRAYIF(品名 <> "", 品名), "、")`。全行を区切りなしでつなぐだけなら `CONCAT(品名)` | `CONCAT(品名, 区切り)` は区切りが各行の**後ろ**に付き（最後にも残る）、空の行は空のまま入る。`TDS` は重複を除いて並べ替える。`TEXTJOIN` はテーブルの列には使えない（1 行目だけ）。表にするなら `TABLE_HTML`（帳票レシピ集） | ✔ |
| 文字をつなぐ | `&` | `"合計 " & SUM(金額) & " 円（" & COUNTROW(明細) & " 行）"` | 数は文字になる（桁区切りは `YEN` など）。**`&` は関数の結果の前後の空白を落とす**（`"sun" & IF(x, " today", "")` → `suntoday`）。空白ごと返すなら `IF(x, "sun today", "sun")` のように全体を 1 つの文字列に | ✔ |
| 変数で式を短く | `LET` | `LET(a, 式a, b, 式b, 結果)`（**1 つの LET に変数を並べる**。後の式で前の変数を使える） | 変数名に項目のコードは使えない | ✔ |
| 文字列の長さ・切り出し・検索 | `LENGTH` / `LEFT` / `RIGHT` / `MID` / `SUBSTR` / `FIND` / `TEST` | `LENGTH(住所)`、`MID(住所, 3, 4)`（位置は 1 から）、`SUBSTR(住所, 3, 4)`（0 から）、`FIND(住所, "千代田")`（0 から数えた位置。無ければ -1）、`TEST(住所, "千代田")`（有無） | 長さは `LENGTH`（`LEN` は無い）。`TEST` は正規表現ではない | ✔ |
| 全角半角・空白・ゼロ埋め・分割 | `ASC` / `JIS` / `TRIM` / `UPPER` / `LOWER` / `RIGHT` / `SPLIT` | `ASC(文字列)`（全角 → 半角）、`JIS(文字列)`（半角 → 全角）、`TRIM(文字列)`、`RIGHT("0000" & 番号, 4)`（ゼロ埋め → 0042）、`ARRAY_GET(SPLIT(文字列, "-"), 1)`（区切りの 2 つ目） | `ASC` / `JIS` は 2 つ目の引数で対象を絞れる（関数一覧） | ✔ |
| 置換（複数の組） | `REPLACEALL` | `REPLACEALL(宛名, ARRAY("(株)", "株式会社", "（株）", "株式会社"))` | — | c81af42029f389b4af40 ✔ |
| 形の検査・取り出し・置換（正規表現） | `TESTRE` / `MATCH` / `REPLACERE` | `TESTRE(郵便番号, "^[0-9]{3}-[0-9]{4}$")`、`MATCH(備考, "A-[0-9]+")`（最初の 1 つ）、`JOIN(MATCH(備考, "A-[0-9]+", "g"), "、")`（全部）、`REPLACERE(ASC(電話番号), "-", "g", "")` → 0312345678 | `TESTRE` は空も false。**`"g"` が無いと最初の 1 つだけ**置き換える。全角の記号は先に `ASC` で半角に | ✔ |

## 大きい帳票の式（印刷屋 Ver.9）

計算式だけで図や譜面を組むような大きい帳票（`docs/samples` の五線譜・盤面図）で使う書き方と、落とし穴。

| やりたいこと | やり方 | 式の例 | 確かめること・注意 | 記事 |
| --- | --- | --- | --- | --- |
| 置換をまとめる（入れ子の `REPLACERE` を 1 回に） | 置換の組の配列 | `REPLACERE(文字列, ARRAY("-", "_", "\s", ""), "g")`、`REPLACEALL(宛名, ARRAY("(株)", "株式会社", "（株）", "株式会社"))` | 先頭の組から順に置換（入れ子と同じ）。flag は全部の組に共通なので、flag の違う組は分ける（flag を省くとどの組も最初の 1 つだけ）。印刷屋 Ver.9 から | ✔ |
| ループで前の回の結果を使う | ループの前の `LET` で決めた変数を、ループの中の `FSET` で書き換える | `LET(s, "x", a, ARRAY_FOR(3, k, FSET(s, CONCAT(s, k))), s)` → x012。1 回に複数なら `ARRAY(FSET(s, s + k), FSET(t, CONCAT(t, s, ",")))` | `ARRAY(…)` の中は前から順に 1 回ずつ評価される。ループの中の `LET` で外と同じ名前に代入しない（外の変数が消える）。印刷屋 Ver.8 では、`CONCAT` の 1 つ目に置いた `FSET` が 2 回評価され、変数の 0 が空になった | ✔ |
| 1 件ずつ・1 手ずつ進める | 状態の文字列に、残りを全部入れない | 盤面図: 状態は「直前の手と盤」だけにし、回ごとに残りの手の先頭の 1 つを入れる（`REPLACERE(r, "^(#[^#]*)[\s\S]*", "$1")`） | 状態に残りを全部入れると、回ごとの正規表現が残りを全部なめ、時間が件数の 2 乗より速く増える（盤面図の 400 手で 5 秒 → 0.3 秒） | — |
| 長い定数（正規表現・表・SVG の部品）を置く | 帳票の行の HTML 欄に JSON で置き、式から読む | `LET(K, JSON_P($html, 0), P, DIC_ITEM(K, "P"), …)`。HTML 欄は検査（使える要素）と `${…}` の置き換えを通るので、`<` `>` `&` は JSON の `\u003c` `\u003e` `\u0026` に（`JSON_P` で元に戻る）、`${` を書かない | 計算式の欄は 2 万字まで、HTML 欄は 20 万字まで。ボタンどうしで定数は共有できない（ボタンごとに置く） | — |
| 落とし穴: 保存の検査で式が重くなる | 長い置換に使うパターンは、HTML 欄の定数でなく式の中に字の定数で書く | 五線譜: タイの正規表現 6 つを字の定数にした | 保存の検査（設定画面の保存・`normalize`）は空の値で式を評価し、HTML 欄の定数も読めないので、定数から読んだパターンは `""` になる。空のパターンを `"g"` で置換すると全部の位置に置換の文字が入り、続く置換で文字が掛け算で増える（五線譜で検査だけで 1 秒・ヒープ約 2 GB → 22 ms） | — |

上限（印刷屋 Ver.9。かっこは Ver.8）: 1 つの式の中の同じ関数・文字列の数 200,000（100 個・1,000 個。超えた分が先に評価されて崩れた）、計算回数 1,000 万回（10 万回）、`ARRAY_FOR` の回数 10 万回（1,000 回）。計算式の欄 2 万字と HTML・CSS の欄 20 万字は同じ。
