# 帳票レシピ集（印刷屋プラグイン Ver.6）

帳票の書き方の決まりと、題材ごとのレシピ。レシピの元は rex0220 の Qiita 記事（印刷屋プラグインの使用例 19 本）で、ここでは全部を**既定の形（HTML テンプレート + `${ESC_HTML(項目)}` + テーブルは `TABLE_HTML`）**に書き直してある。記事の計算式だけの形（`PAGE_HTML` + `TAG`）も動くが、AI の既定にはしない。
（段階 1 の版。請求書・QR と画像・テーブル + カード・背景画像・グラフのレシピと samples は段階 2 で足す）

## 0. 既定の形

HTML 設定の 3 行目（本文）は、**HTML 欄にテンプレート**、**計算式欄にテーブルの差し込み**を書く。

HTML 欄:
```html
<div class="rex0220-pcraft-page">
  <div class="pcraft-inv-header">見積書</div>
  <p>${ESC_HTML(宛名)} 御中</p>
  <p>見積金額: ${FVAL(合計)}　発行日: ${DATE_FORMAT(見積日, "YYYY年M月D日")}</p>
  ##table##
  <div class="pcraft-inv-remarks-section">${REPLACE(ESC_HTML(備考), NEWLINE(), "<br>")}</div>
</div>
```

計算式欄:
```
LET(
  table, TABLE_HTML(見積明細,
    OPT("pref", "pcraft-inv-item-"),
    ARRAY("#", ROWNO(見積明細) + 1),
    商品名, 数量, 単価, 金額
  ),
  REPLACE($html, "##table##", table)
)
```

決まり:

- 文字列は `${ESC_HTML(項目)}`。金額・日付は `${FVAL(項目)}` / `${DATE_FORMAT(項目, "書式")}`。複数行は `${REPLACE(ESC_HTML(項目), NEWLINE(), "<br>")}`（計算式の文字列は `\` を解釈しないので `"\n"` は改行にならない。改行は `NEWLINE()`）
- **`${式}` を属性値に置かない**。class や style は固定で書き、値で見た目を変えたいときは、固定の候補から計算式で選ぶ（例: `${IF(状態 = "済", "<span class='done'>済</span>", "")}` のように、レコードの値そのものは属性に入れない。計算式の文字列の中では HTML の属性を `'` で囲む（`\"` は `\` が残って class が効かない。下の「つまずきと切り分け」）。`TAG` / `ATTR` でレコードの値を属性にすると `normalize` が警告する。`ATTR` の値はエスケープされない）
- **インラインの `<svg>` は使わない**（`normalize` がエラー）。社印などの図は `<img src="data:image/svg+xml,…">` か添付ファイルの `#{&f(fileKey)}`。使える要素と属性は文章・表・画像のもの（`docs/設定ファイル仕様.md` 3 章）
- テーブルは `TABLE_HTML` を `##table##` の目印に差し込む（目印は `##名前##` の形で何個でも）。`TABLE_HTML` のセルはエスケープされないので、信頼できる項目だけを並べる
- 1 ページは `<div class="rex0220-pcraft-page">…</div>`。用紙に固定で、はみ出しは切れる。印刷屋がページに当てる CSS は `position: relative; padding: 40px 40px 40px 60px; box-sizing: border-box; overflow: hidden;` と用紙の幅・高さ（96 dpi で A4 縦 794 × 1123 px、A4 横 1123 × 794 px、A3 縦 1123 × 1587 px。150 dpi は A4 縦 1240 × 1754 px。px = mm × dpi ÷ 25.4）。帳票の CSS で上書きできる
- ページ番号は、ページの中に `#{&p}`（そのページの番号）と `#{&n}`（総ページ数）を書く。右下に置くなら、ページが `position: relative` なので `<div class="pcraft-page-no">#{&p} / #{&n}</div>` と CSS `.pcraft-page-no { position: absolute; right: 40px; bottom: 20px; }`（表紙と本文のようにページを HTML で書くときはこれで足りる。`TABLE_HTML` の `pagination` で分けたページには R4）
- CSS は共通 CSS（既定の 4 行。`docs/defaults/cssInfo.json`）の class を使い、帳票の CSS 欄には差分だけ。既定の見積書の class は `pcraft-inv-header` / `pcraft-inv-info` / `pcraft-inv-left` / `pcraft-inv-right` / `pcraft-inv-seal` / `pcraft-inv-estimate-amount` / `pcraft-inv-validity` / `pcraft-inv-item-table`（`TABLE_HTML` の `pref` `pcraft-inv-item-`）/ `pcraft-inv-summary-section` / `pcraft-inv-remarks-section` / `pcraft-inv-total-section` / `pcraft-inv-footer`
- ボタン表示条件（1 行目）とファイル名（2 行目）は必ず書く。例: `NOT(見積ファイル)`（まだ PDF が無いとき）、`"見積書-" & 見積番号 & ".pdf"`

## R2. CSS の差分と共通 CSS 化

元: 「見積書のCSSカスタマイズ」「〃２」「共通CSSを追加」。

- 少し変えるなら帳票の CSS 欄に差分だけ（共通 CSS の後に当たるので勝つ）:

```css
.pcraft-inv-item-table thead { background-color: #2c3e50; color: white; }
.pcraft-inv-item-table th, .pcraft-inv-item-table td { border: 1px solid #ddd; }
.pcraft-inv-item-table tbody tr:nth-child(even) { background-color: #f2f2f2; }
```

- 大きく変えるなら class 名を付け替える（例 `pcraft-inv-*` → `pcraft-est-*`）: HTML の class と `TABLE_HTML` の `OPT("pref","pcraft-est-item-")` と CSS をそろえる。複数の帳票で使うなら `cssInfo` に行を足して共通 CSS にする（既定の 4 行はそのまま残す）

## R4. テーブルの複数ページ

元: 「テーブル複数ページ」。行数が多いテーブルは `TABLE_HTML` にページを切らせる。各ページが `rex0220-pcraft-page` になる。

```
TABLE_HTML(テーブル,
  OPT("title", "商品一覧", "pagination", "Y", "perPage", "20"),
  ARRAY("#", ROWNO(テーブル) + 1, "row-no"),
  名称, 数量, 金額
)
```

- このときは HTML 欄を空にして計算式だけにする（テンプレートの 1 ページの中にはページを入れられない）。見出しや日付を各ページに付けたいときは `OPT("title", …)` を使う
- CSS: `.pcraft-table-row { height: 60px; }` のように行の高さを固定すると、ページの行数が安定する
- ページ番号は `OPT` では付かないので、`#{&p}` / `#{&n}` を使いたいときは計算式でページを組む（`TAGS_HTML(ARRAY_MAP(…, PAGE_HTML(…)))`。`帳票関数リファレンス.md` 5 章）

## R5. 一覧帳票（一覧画面のレコードを表に）

元: 「一覧画面のPDF作成」「一覧画面の合計欄」「一覧画面をカード形式で表示」。

- ボタン: `list: true`、`filecode: ""`（ダウンロードだけ）、横長なら `orientation: "l"`。`viewsCsv` で出す一覧を絞れる（一覧 ID は利用者に聞く）
- HTML 欄は空、計算式だけ:

```
RECS_HTML(
  OPT("title", "案件情報 " & DATE_FORMAT(TODAY(), "YYYY年M月D日"), "pagination", "Y", "perPage", "10", "footer", "Y"),
  ARRAY("#", $rseq + 1),
  顧客名, 部署名, 案件名,
  ARRAY("確度", 確度, "value-center"),
  ARRAY("プラン費用", YEN(プラン費用), "value-right", "YEN(RECS_SUM(プラン費用))"),
  ARRAY("合計費用", YEN(合計費用), "value-right", "YEN(RECS_SUM(合計費用))")
)
```

- `$rseq` が順番（0 から）、`RECS_SUM(項目)` が合計、`ARRAY` の 4 つ目は合計欄の式（文字列で渡す）。`OPT("type","card","hideLabels","Y","perPage","8")` でカード形式
- 1 レコードの `preview` では確認できない。印刷屋の一覧画面で「選択したレコードのみ一括処理」も含めて確かめる

## R6. ボタン表示条件・ファイル名・更新項目の定番

元: 「ボタン表示制御」「ボタン表示権限」、見積書アプリの設定。

| 目的 | 書き方 |
| --- | --- |
| PDF が無いときだけボタンを出す | `$out`: `NOT(見積ファイル)` |
| ステータスが「承認」のときだけ | `$out`: `ステータス = "承認"` |
| 所属組織で出す | `$out`: `IN(OINFO(UINFO(LOGIN_CODE(), "primaryOrganization"), "code"), "sales")`（組織コードは利用者に聞く） |
| ファイル名に日付 | `$fname`: `"見積書-" & 見積番号 & "-" & DATE_FORMAT(TODAY(), "YYYYMMDD") & ".pdf"` |
| 作成後にチェックを付ける | 更新項目 `発行済み`: `ARRAY("済")`（チェックボックスは配列） |
| 作成後に日時を入れる | 更新項目 `発行日時`: `NOW()` |
| 古い PDF を 1 つだけ残す | 更新項目 `見積ファイル`: `FSET(見積ファイル, SLICE(見積ファイル, -1))` |

権限（`authority: true` + `users` / `organizations` / `groups`）はコードの CSV。コードは推測せず利用者に聞く。

## R7. Web フォント（PC・Mac・スマホで同じ字形）

`fontInfo`: `{ "enabled": true, "preset": "other", "family": "BIZ UDPMincho", "cssUrl": "https://fonts.googleapis.com/css2?family=BIZ+UDPMincho:wght@400;700&display=swap" }`。帳票全体に効かせたいときは、帳票の CSS と HTML でページ（`.rex0220-pcraft-page`）にも中の要素にも `font-family` を書かない。印刷屋 Ver.6 はページに書いた書体が勝つ（読み込まない書体の名前なら OS の書体になる）。Ver.7 は書体を読み込めたらページの書体を Web フォントに置き換えるが、中の要素（見出し、`td` など）に書いた `font-family` は Ver.7 でも勝つ。Google Fonts は承認済み。それ以外の配信元は利用者が `policy/` に書く。

スマホの詳細画面のボタンは Web フォントが有効なとき（`enabled` が真で、`family` と https の `cssUrl` が正しい）だけ出る。スマホでも使う帳票なら有効にする。

## R8. 関連レコード一覧（親$子。印刷屋 Ver.8）— 工程表

関連レコード一覧（`REFERENCE_TABLE`）が指すレコードを、テーブルと同じ関数で帳票にする。例はガントチャートアプリの工程表（プロジェクトのレコードから、関連レコード一覧 `task_list` のタスクを親子の階層で並べる。実機で確認済み。`docs/samples/工程表/` に設定・項目定義・見本のレコード・プレビュー）。

決まり:

- 参照先の項目は **`<関連レコード一覧のフィールドコード>$<参照先のフィールドコード>`**（半角の `$`）。`fields --summary` に字下げで出る（例 `task_list$task_name`、`task_list$start_date`）。参照先のレコードの中のテーブルは使えない
- 使える関数はテーブルと同じ: `TABLE_HTML(task_list, …)`、`TABLE_DIC(task_list, …)`、`SUM(…)`、`COUNTROW(task_list)`、`ROWNO(task_list)`、`ROWID(task_list)`（参照先のレコード ID）、`SUBTABLE(task_list$start_date)`（列の配列）、`TPFILTER(…)`
- 読み取りだけ（`FSET` / `FSET_TADD` は使えない）。**ボタン表示条件（1 行目）・更新条件・一覧用のボタンでは使えない**（normalize がエラーにする。画面を開いたときには関連レコードが無いため）。ボタン表示条件は本体の項目で書く（例 `record_type = "project"`）
- 印刷屋は詳細画面のボタンを押したときに、関連レコード一覧の条件・絞り込み・並びで参照先のレコードを取る（画面の表示件数は使わない。**1 つの関連レコード一覧につき 1,000 件まで。超えると帳票を作らない**）。利用者に参照先を見る権限が要る。関連レコードを使う帳票は、共通の設定の「外部参照を許可」でも kintone 以外への読み込みとスクリプトを除く
- 計算式の文字列の中で HTML の属性を書くときは `'` で囲む（`"<div class='bar'>"`。`\"` は `\` が残る。「つまずきと切り分け」）
- tools: `fields --app N` が参照先の項目定義を `fields.json` の `related` に入れる（API トークンの接続では参照先のアプリのトークンも `tokenMap` に）。`record --app N --id R --fields-from <設定>` が参照先のレコードも仮のテーブルとして入れるので、`preview` で確かめられる

### 作り方（工程表）

HTML 欄は空にして、計算式だけで組む（1 ページ目だけ本体の項目を置くため）。

```
LET(
  // 概要（件数・完了・期間）。COUNTROW / SUM / SUBTABLE は関連レコードの仮のテーブルで動く
  total, COUNTROW(task_list),
  done, SUM(IF(task_list$task_situation = "done", 1, 0)),
  period, IF(total > 0, DATE_FORMAT(MIN(SUBTABLE(task_list$start_date)), "YYYY-MM-DD") & " 〜 " & DATE_FORMAT(MAX(SUBTABLE(task_list$end_date)), "YYYY-MM-DD"), ""),
  // 親子: uuid → 親タスク ID の表（親の親まで辿る。並びは display_order なので親の下に子が並ぶ）
  parents, TABLE_DIC(task_list, task_list$uuid, task_list$parent_task_id),
  title, "工程表 " & ESC_HTML(project_name) & "<small>タスク " & total & " 件、完了 " & done & " 件</small>",
  // 1 ページ目のプロジェクト情報（本体の項目）
  info, "<table class='pcraft-gantt-info'><tbody>"
    & "<tr><th>プロジェクトコード</th><td>" & ESC_HTML(project_code) & "</td><th>状態</th><td>" & project_status & "</td></tr>"
    & "<tr><th>責任者</th><td>" & ESC_HTML(manager_name) & "</td><th>期間（タスク）</th><td>" & period & "</td></tr>"
    & "</tbody></table>",
  // 1 ページ目: 見出し + 情報 + タスク 24 行（ROWNO は 0 から）。ページ番号は #{&p/&n}
  page1, "<div class='rex0220-pcraft-page'><div class='table-header'><span class='table-header-title'>" & title & "</span> <span class='table-header-page'>(#{&p/&n})</span></div>" & info
    & TABLE_HTML(task_list,
      OPT("filter", ROWNO(task_list) < 24, "pref", "pcraft-gantt-"),
      ARRAY("#", ROWNO(task_list) + 1),
      // 親は太字、子は階層の分だけ字下げ（3 段まで）
      ARRAY("タスク名", LET(
        p1, task_list$parent_task_id,
        p2, IF(p1 = "", "", DIC_ITEM(parents, p1)),
        p3, IF(p2 = "", "", DIC_ITEM(parents, p2)),
        name, ESC_HTML(task_list$task_name),
        IF(p1 = "", "<b>" & name & "</b>", IF(p2 = "", "　└ " & name, IF(p3 = "", "　　└ " & name, "　　　└ " & name))))),
      ARRAY("担当者", ESC_HTML(task_list$assignee_name)),
      task_list$start_date,
      task_list$end_date,
      ARRAY("進捗", "<div class='pcraft-gantt-bar'><div class='pcraft-gantt-fill' style='width:" & IF(task_list$progress = "", 0, task_list$progress) & "%'></div></div>" & IF(task_list$progress = "", 0, task_list$progress) & "%"),
      ARRAY("MS", IF(task_list$milestone = "ON", "◆", "")))
    & "</div>",
  // 2 ページ目以降: 残りを 28 行ずつ（TABLE_HTML の pagination がページを作る。列は 1 ページ目と同じものを書く）
  rest, IF(total <= 24, "",
    TABLE_HTML(task_list,
      OPT("title", title, "filter", ROWNO(task_list) >= 24, "pagination", "Y", "perPage", "28", "maxPages", "40", "pref", "pcraft-gantt-"),
      ARRAY("#", ROWNO(task_list) + 1),
      … 1 ページ目と同じ列 …)),
  page1 & rest
)
```

- `OPT("filter", 式)` は行ごとに評価される（`ROWNO(task_list)` は 0 から）。1 ページ目の行数（24）はプロジェクト情報の高さに合わせる（A4 横 96dpi で情報の表 4 行なら 24、表を減らせば 26 程度）。2 ページ目以降は 28。概要が長いときは 1 ページ目をさらに減らす
- `pagination` のページには `TABLE_HTML` が見出し（`title` と `#{&p/&n}`）を付ける。1 ページ目は自分で同じ形の見出しを書く
- 1,000 件に近いと計算に十数秒かかる（1,000 行で 16 秒・36 ページの測定）。実用は数百件まで。多いときは関連レコード一覧の「さらに絞り込む条件」で減らす
- CSS: `.pcraft-gantt-table` / `.pcraft-gantt-head` / `.pcraft-gantt-row` / `.pcraft-gantt-bar` / `.pcraft-gantt-fill` / `.pcraft-gantt-info` / `.table-header` / `.table-header-page`（`docs/samples/工程表/settings-source.json`）
- スマホでも使うなら `fontInfo` を有効にする（モバイルの詳細画面のボタンは Web フォントが有効なときだけ。R7）

## つまずきと切り分け（記事で見つかったもの。2026-10-12）

Qiita の記事（`docs/qiita/`。資産ラベル、組織図、文書一式、デザイン）で実際に起きたこと。`normalize` は機械で判定できて原因がはっきりしているものだけ**情報**で知らせる（エラーにはしない。事例が 1 件で原因が分からないものは知らせない）。

| つまずき | 直し方 | normalize |
| --- | --- | --- |
| **mm で書いた寸法が約 0.64 倍に縮む**（150dpi）。印刷屋は用紙と dpi からページの px を決めるが、CSS の mm は 96dpi 換算（1mm = 3.78px） | 実寸を合わせる帳票（ラベル）は **96dpi** にする。150dpi のままなら px = mm × 150 ÷ 25.4 で書く | `page.dpiMm` |
| **プレビューでは出る文字が PDF で消える**。`display: inline-block` の箱（背景色 + 白い文字）で起きた事例 1 件（原因は未確認。既定の見積書の CSS も inline-block を使っていて問題は無い） | 消えたら `display` を block にして `margin: 0 auto` で置く | 判定しない |
| **HTML の属性が効かない**。計算式の文字列の中の `\"` は印刷屋が `\` を取り除かないので、`"<span class=\"x\">"` は `class=\"x\"` のまま出る | 属性は `'` で囲む: `"<span class='x'>"` | `formula.backslashQuote` |
| **複数の帳票を 1 つの設定にまとめる**（帳票の CSS はボタンごとに読まれるので干渉はしないが、見比べるときや共通 CSS に移すときに紛れる） | 帳票ごとにクラス名の頭を分ける（`pcraft-q-` / `pcraft-po-` / `pcraft-bill-`） | 判定しない |
| **1 ページ目だけ白紙**。`ARRAY_FOR(n, idx, idx)` のループ変数（0 始まり）をページの番号として `ARRAY_MAP` の変数で受け、比較に使ったら 1 ページ目の分が選ばれなかった（内部の理由は未確認） | ページや面の番号は **1 から数える**（`ARRAY_FOR(n, vI, vI + 1)`） | 判定しない |

切り分けのコツ（記事より）:

- **「プレビューでは出る / PDF で出ない」のように違いを伝える**（プレビューと PDF は描画が違う。README のトラブルシュート）。違いが分かると原因の範囲がしぼれる
- **条件を 1 つずつ変えたボタンを並べる**（QR の有無、dpi、1 ページの面数など）。どれも同じ結果なら、その条件は原因でない
- **帳票の中に式の途中の値を出す**（ページの番号、選んだ件数）。見えない値を見えるようにする
- **PDF を AI に読ませる・測らせる**（寸法の割合から dpi の問題を見つけた）
- **危ないところから先に試す**（「CSS の線が PDF に出るか」をアプリより先に確かめ、手戻りを避けた）
- **「はみ出た」が前の設定の描画だったことがある**。取り込み直したか（置き換えたボタンか）を先に確かめる

検査が見ないもの（人が PDF で確かめる）: 見た目、1 ページに収まる行数、長い値での崩れ、書体（PDF を作る PC の書体。どの PC でも同じにするなら Web フォント）、仮の値（会社名・社印・登録番号・振込先は取り込む前に差し替える）、請求書の記載事項（登録番号、取引年月日など。経理や税理士に確かめる）。日付の意味は帳票ごとに違う（見積日 / 記入用の空欄 / 発行した日）ので、決まった日付を載せるならアプリに項目を足す。一覧帳票は試し出力の対象外で、一覧画面のレコードは最大 100 件。
